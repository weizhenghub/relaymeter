v0.191  2026-08-26

修复：
- **「切换失败: timed out」弹窗**。GUI `set_passthrough_mode` 之前用同步 `urllib.request.urlopen(req, timeout=2.0)` 直连中继打 `/api/passthrough/mode`（PUT）。中继是独立 uvicorn 进程、每 worker 单线程事件循环；当它正在往上游慢速**流式**一个大图响应（实测约 6s 窗口）时，新来的 /api/passthrough/mode 请求会排在那个 stream 后面，socket 读在 2.0s 超时弹错 —— 即使中继本身完全健康。这跟代码库早就解决的「桥线程卡死」是同一类问题（`_pid_executor`）。
- 顺带：该同步调用跑在 GUI bridge 线程池里，阻塞期间连其它按钮点击都会卡住。两个问题一处修。

实现：
- `gui.py`：
  - 新增模块级 `_passthrough_executor = ThreadPoolExecutor(max_workers=1, thread_name_prefix="relay-passthrough-http")` 和 `_PASSTHROUGH_HTTP_TIMEOUT = 15.0`（镜像 `_pid_executor`/`_PID_LOOKUP_TIMEOUT` 的既有模式）。
  - `get_passthrough_mode` / `set_passthrough_mode` 改为 `_passthrough_executor.submit(...)` 在专用 worker 里发起 GET/PUT，`future.result(timeout=15.0)` 等待；桥线程不再被网络阻塞。
  - 新增两个 worker 辅助函数 `_http_get_json` / `_http_put_json`；把 `_PASSTHROUGH_HTTP_TIMEOUT` 同时作为传给 `urlopen` 的 socket timeout（旧 2.0s 停在 socket 层，即使放进 worker 也会在 busy 窗口触发超时，必须一并放宽）。
  - 未改其它透传端点（get_passthrough_upstreams / rename 等）—— 它们是只读/低频，无此卡死场景。

v0.185  2026-08-26

修复：
- **总览卡片边缘拖拽失效 + 列跨度只能 3 档 + 光标跳变（一组 5 个累积 bug，用户反馈「上下拖动很正确。但是左右完全拖不动」「按下后...鼠标样式回归普通样式」「拖动没用」「需要修正为20挡位」）**：
  - **起点坐标系错位**（导致"按下跳变 + 拖动无效"）：mousedown 旧逻辑 `startH = 实测内容高 (27.5px)` 但 `st.height = 吸附档 (200px)`，move 端 `newH = 27.5 + dy`，要 dy > 212px 才能跨过中点到 280 档。修法：`startH = OVERVIEW_HEIGHTS[initSnap]`，跟 `st.height` 同坐标系，dy > 10px 即跨档。
  - **CSS Grid `span <integer>` 不接小数**（导致"左右完全拖不动"）：CDP 实测 `--ov-span = 1.5/2.5/2.8` 全部被静默丢弃，卡永远 1 列宽（313px）。这是 CSS spec 硬限，不是浏览器 bug。要 fine-grained 必须换布局机制。
  - **WebView2 `cursor: inherit !important` 退化**（导致"鼠标样式回归普通样式"）：`body.x * { cursor: inherit !important }` 选择器在 WebView2 下把 body 自身 cursor 也变 inherit → 解析为 auto（body 没父级）。用户看到的是普通光标，不是预期的 ns-resize / ew-resize。
  - **悬停 translateY(-3px) 覆盖命中区**（导致"按下后卡瞬回上浮 + 光标跳回 grab"）：`.glass-card:hover` 把命中区跟着卡上抬 → 鼠标脱离命中区 → cardResizePointerDown 早返回 → wireEdgeResize 接管 cursor。
  - **20 档循环边界 i<20 → 2.9**（导致"只能吸到 2.9，到不了满 3 列"）：`for (i=0; i<20; i++)` 写到 i=19 = 2.9 就停，3.0 永远进不来。

实现：
- **布局切换**：总览 `.view[data-view="overview"] > .grid` 从 CSS Grid 切到 `display: flex; flex-wrap: wrap; gap: 16px !important;`；卡 `width: calc(var(--ov-span, 1) / 3 * (100% - 32px)) !important`（32px = 2×16px 行内 gap 总和）。`!important` 兜底 file:// CDP 抓不到的特异性坑（`gap` 不加会被压成 6px）。`.glass-card:hover { translateY(-3px) }` 在 `body.card-resizing` 期间 `transform: none !important` 禁掉。`.card-chart-row` 的 `grid-column: span 2` 在 flex 下变 no-op，注释同步更新。
- **列跨度 21 档**：OVERVIEW_SPANS `[1, 1.1, ..., 2.9, 3.0]`（循环 `i <= 20`，闭合到 3.0）。
- **高度 31 档**：OVERVIEW_HEIGHTS `[160, 180, ..., 760]` 步长 20px，move 端 `newH = clamp(round(st.startH + dy))`。
- **光标**：三个 mode 类直接写具体 cursor 值（`body.card-resizing-h * { cursor: ns-resize !important }` 等），**不用 inherit**。
- **命中区在卡内**：`.card-edge-bottom { bottom: 0; height: 8px }`、`.card-edge-right { right: 0; width: 8px }`，全部在 `.glass-card` 视觉边界内，`.glass-card { overflow: hidden; border-radius }` 裁两角但其它位置全可命中。
- **min-height 兜底**：`.card-body[style*="--ov-h"]` 规则加 `min-height: 0 !important`（解除 stats-chart-host / `[data-card^="stats-"]` 的 220 下限，否则拖到 220 以下被静默夹住）。
- **wireEdgeResize 互斥**：`cardResizePointerDown` 头部 `e.stopImmediatePropagation()`（而非 stopPropagation，capture 队列才会断）；wireEdgeResize mousemove 检查 `!body.card-resizing` 才写 cursor。
- **起点对齐**：mousedown 算 `baseH = s0.height > 0 ? s0.height : clampH(measuredH)`，再 snap 到 OVERVIEW_HEIGHTS，`startH = OVERVIEW_HEIGHTS[initSnap]`。

- min-height 优先于 height，stats 类卡的 220 下限要显式解除才能拖到 220 以下。
- 改完前端静态文件必须 bump `index.html` 里的 `?v=...` 版本号，否则浏览器复用旧 CSS/JS。

- 不影响其他视图（history / upstreams / opencode 仍走原 CSS Grid / flex column 规则，selector `.view[data-view="overview"] > .grid` 严格限定总览）。

- **侧栏整页白屏无 UI（ERR_FILE_NOT_FOUND，上一轮的回归）**：初版把主题参数写成了顶层 URL 的 `?query`（`live_panel.html?theme=day&v=…`）。WebView2 对顶层 `file://` 导航会把 `?query` 当**文件系统路径** → 文件解析失败 → `ERR_FILE_NOT_FOUND` → 整页白屏完全无 UI（用户截图实锤）。修复：顶层 `file://` URL 用 **hash fragment**（`#theme=`）传参 —— fragment 只在客户端参与、不参与文件路径解析，文件正常加载，首帧仍能读主题。⚠ 约束：顶层 `file://` 导航不可带 `?query`；子资源 query（`<script src="...?v=NNN">` / `<link href="...?v=NNN">`）不受此限，照常做缓存 bust。
- **球 Z 序被侧栏盖住**：pywebview `resize()` 用 `hWndInsertAfter=NULL`（HWND_TOP）会把侧栏抬到 TopMost band 顶部，而球 `WS_EX_NOACTIVATE` 永不自动抬顶 → 侧栏反盖球。`ball_layer.py` 新增 Z 序保活定时器（`_topkeep_timer`，300ms 周期 `SetWindowPos(HWND_TOPMOST, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)`），球恒居 TopMost band 顶。
- **侧栏不跟随悬浮球 + 主窗无法拖动（v0.170 Z 序保活的回归，用户反馈「侧边栏又没跟随悬浮窗了，直接卡在固定位置」「主窗口没法拖动移动位置了」）**：`ball_layer._load_user32()` 在**共享** `ctypes.windll.user32` 实例上设了 `SetWindowPos.argtypes`（cx/cy 声明成 `c_int`）。pywebview 的 `winforms.py` `move()` 也走 `windll.user32.SetWindowPos`，但它对 cx/cy 传 `None`（依赖 ctypes **未设 argtypes** 时的宽松转换）→ 每次 `ww.move()` 抛 `ctypes.ArgumentError: argument 5: NoneType` → 侧栏所有 move 失败、卡死固定位置不跟随球；主窗/侧栏都是 frameless + easy_drag（拖动靠 pywebview `move()`）→ 主窗同样无法拖动。修复：`_load_user32()` 改用**私有** `ctypes.WinDLL("user32", use_last_error=True)` 实例（模块级 `_user32` 缓存）—— argtypes 只作用于球自己的 `SetWindowPos(HWND_TOPMOST)` 调用，不再毒害 pywebview 共享的 `windll.user32`。

影响面：
- 仅球/侧栏层级相关。不改悬浮球开关、拖动、磁吸逻辑。
- 默认值 True = 行为与 v0.169 完全一致（球恒置顶、侧栏在 dock 态因 AddOwnedForm 随主窗）；只有用户关掉「悬浮球置顶」才让两者一起降级。

测试：
- `py_compile` 全部修改的 Python 文件 + `node --check` app.js 通过。
- 手动验收：开悬浮球 → 侧栏浮动展开 → 打开一个全屏/高窗口盖住侧栏位置 → 侧栏仍在最上面（与球同层级）；关「悬浮球置顶」→ 球与侧栏一起被高窗口盖住；重启 GUI 开关状态保留。
- 手动验收两条回归（⚠ 不要再踩）：(1) 重启 GUI >5 次 → 侧栏正常加载、无白屏无 UI（ERR_FILE_NOT_FOUND 已修，URL `#theme=` 非 `?theme=`）；(2) 拖动主窗 + 拖动悬浮球 → 主窗能自由移动、侧栏实时跟随球（argtypes 私有 WinDLL 已隔离，不再毒害 pywebview）。

v0.171  2026-08-25

修复：
- **侧栏延展/收缩时悬浮球反复闪烁（用户反馈「侧边栏延展或收缩时，悬浮窗会在『悬浮在侧栏上面』和『被侧栏遮挡』两个状态间反复闪烁几次」）**：根因是 pywebview `winforms.py:616` 的 `Form.resize()` 走 `SetWindowPos(handle, None, x, y, w, h, 64)` —— flag `64 = SWP_SHOWWINDOW`，`hWndInsertAfter=None`(= `HWND_TOP`)，**没有 `SWP_NOZORDER`**。这意味着侧栏**每帧 resize 都被抬到 Z 序顶**。宽度补间动画（`_anim_resize`，32 帧 × 22ms ≈ 700ms）期间，悬浮球的 Z 序保活（v0.170 `_topkeep_tick`，300ms 一次 `SetWindowPos(HWND_TOPMOST)`）又把球压回最顶 —— 两个机制交替胜出，动画期间球在「悬浮在侧栏上面」↔「被侧栏遮挡」间反复闪烁 2-3 次（700ms / 300ms ≈ 2-3 次）。`move()` 反倒是 z-order-safe（带 `SWP_NOZORDER`，winforms.py:642），**只有 `resize()` 是肇事者**。

  解法：完全绕开 pywebview 的 `resize()`，新增 `panel_pool._resize_safe(w, to_w, to_h)` helper 自己调 `SetWindowPos(SWP_NOMOVE|SWP_NOZORDER|SWP_NOACTIVATE = 0x16)` —— 不搬位置、不改 Z 序、不抢焦点；侧栏尺寸仍由我们精确控制（logical→physical 乘 `native._scale`，与 pywebview 同口径），但 resize 不再顺带把侧栏抬到顶，球恒在上层。
  - **私有 user32 实例（沿用 v0.170 教训）**：用 `ctypes.WinDLL("user32", use_last_error=True)` 模块级缓存，不碰共享 `ctypes.windll.user32`。本次再次踩到的坑：共享实例设 `argtypes` 会让 pywebview 的 `move()` 抛 `ArgumentError: argument 5: NoneType`（pywebview 对 cx/cy 传 `None`，依赖 ctypes 未设 argtypes 时的宽松转换）→ 侧栏 move 失败 + 主窗无法拖动，与 v0.170 是同一根因。私有 WinDLL 的 argtypes 只作用于本次 `SetWindowPos` 调用，不污染 pywebview。
  - **句柄 `ToInt64()`（沿用 v0.170 教训）**：pythonnet 3.x 的 `IntPtr` 不能直接 `int()`（抛 TypeError），必须 `h.ToInt64()`（`ball_layer._handle_int` 同惯例）。
  - **失败回退 `w.resize()`**：任何异常回退到 pywebview 的 `resize()`（宁可回到旧闪烁也要侧栏尺寸正确；尺寸错位会挡主窗，闪烁只是视觉痛点）。
  - **5 处调用点改走 `_resize_safe`**：`_anim_resize` 内 3 处（动画帧 1、动画帧 i、收尾精调）+ `_apply_geometry` 内 2 处（球模式仅高度变化、磁吸模式仅主窗高度变化）。`move()` 不动（本身已 z-order-safe）。

实现：
- `panel_pool.py`：新增 `_resize_safe(w, to_w, to_h)`（约 55 行含注释），5 处 `ww.resize()` 替换为 `self._resize_safe(ww, ...)`；原 `import ctypes` 仍可用、helper 局部 `from ctypes import wintypes` + 局部 `WinDLL("user32", use_last_error=True)`。

影响面：
- 仅侧栏 Z 序相关，不动球的置顶/保活机制、不动 ball_layer.py。
- v0.170 「悬浮球置顶」开关关闭路径未变（侧栏降级到普通层级，resize 仍 z-order-safe，但因已不在 TopMost band，无闪烁可发）。
- 顺带修掉了「仅侧栏高度变化时也顺带升 Z 序」的小副作用（磁吸 + 主窗 resize 期间，侧栏 resize 不再每帧抢顶位，对其它 OS 窗口更友好）。

测试：
- `py_compile src/relay/panel_pool.py` 通过。
- 手动验收（⚠ 与 v0.170 同样口径，无自动化）：触发并发请求（侧栏 1→2 列）→ 球全程稳定悬在侧栏上方、无闪烁；并发结束（2→1 列）→ 球全程稳定、无闪烁；延展期间拖动球、点击球、拖主窗均不受影响。

资源版本：无（纯后端，无 JS/CSS cache 变动）。

开发文档：docs/dev/sidebar_resize_zorder_safe_v0.171.md（含 ⚠ 重要参考：pywebview `winforms.resize` Z 序副作用 + 共享 user32 毒害坑，标记为「所有新增对侧栏/球的 resize 路径都必须走 `_resize_safe`，不能直接调 `w.resize()`」）。

- **启动时侧栏误显示（用户反馈「没开实时流侧栏侧栏却在」）**：三处启动强显（`PanelPool.start` / `gui._on_loaded` / `gui._on_panel_loaded`）原用 `live_panel OR always_one` —— `always_one` 默认 `True` 时，即使主开关关或处于悬浮球模式，侧栏也被强显。统一 gate 到新增 `pool._should_show_on_startup()` = `live_panel AND not float_ball AND always_one`：主开关关 → 启动不显示；悬浮球模式 → 侧栏空闲隐藏（由球 S1/S2 控制）；磁吸 + always_one ON → 常驻显示；磁吸 + always_one OFF → 首个请求再弹。
- **拖动悬浮球卡顿（用户反馈）**：拖动流畅度由 `_MOUSE_POLL_MS` 决定（球直接跟光标，每 tick 一次 `UpdateLayeredWindow` 重定位）；30ms≈33fps 有明显卡顿感。降到 15ms（≈64fps；WinForms Timer 分辨率下限 ~15.6ms，再小被系统取整无意义）。侧栏跟随节流 `_FOLLOW_MS=50` 不变 —— 那只是「侧栏 relayout」频率，不是球定位帧率。
- **S2 折叠后侧栏被弹回（用户反馈「延展或收回时侧栏又弹出」）**：根因是 pywebview WinForms 后端的 `move()`/`resize()` 底层 `SetWindowPos` 带 `SWP_SHOWWINDOW` —— 对**隐藏窗**调用会把窗口重新显示。S2 隐藏模式 `_hide_always_one` 置 `always_one_visible=False` 但**不**置 `always_one_manually_hidden`，流式容器增减 → `reportWidth` → `request_width` → `_relayout` → `_apply_geometry`（球分支贴球位）仍 enqueue move/resize → 侧栏被弹回。修复两层：(1) `_apply_geometry`（球模式/磁吸通用）新增 `force_apply` 参数 —— 非 show 路径且隐藏态直接跳过原生 move/resize（几何只缓存，留给 `_show_always_one` 定位），`_show_always_one` 改传 `force_apply=True` 强制应用；(2) `_hide_always_one` 折叠时 `_width_anim_seq += 1` 失效在飞的宽度补间动画 —— 否则动画线程每 22ms 连发 `resize()`（SWP_SHOWWINDOW）把隐藏窗持续弹回。

影响面：
- 仅 GUI/侧栏侧。uvicorn 8088 proxy 路径零改动。
- 互斥改变「始终开启一个」的生效域：浮动（球）模式下该选项不再生效，侧栏显隐完全由球 S1/S2 控制。
